## 1. 产品概述

### 1.1 产品定位

**FlowShelf** 是一款 AI 原生的"个人数字资产管家"，通过**浏览器扩展 + Web 应用**的形态，帮助用户管理三类数字资产：

| 资产类型 | 性质 | 用户动作 | 终态 |
|---|---|---|---|
| 📚 **知识** | 流转中 → 沉淀 | 阅读 + 生成卡片 | 知识卡片库 |
| 🛠 **工具** | 反复使用 | 一键收藏 | 工具箱 |
| 🧩 **临时** | 即开即用 | Tab 治理 | 关闭即消失 |

### 1.2 一句话定位

> **你的 AI 数字信息管家——从信息洪流中沉淀个人知识资产，永不丢失常用工具。**

### 1.3 产品背景

#### 用户痛点

1. **Tab 焦虑**：开 50+ 标签后无法定位、不敢关闭
2. **收藏夹失效**：传统文件夹模型在信息爆炸下结构性失败——A 文件夹混入 B/C 内容，"我记得收藏过但找不到"
3. **阅读无沉淀**：读完即忘，无法回溯"我读过哪些关于 X 的内容"
4. **数字资产碎片化**：知识、工具、临时信息散落在数十个工具中

#### 行业判断

- 单点工具（Tab 管理、收藏夹、稍后读）竞争已白热化
- **"信息获取 → 整理 → 沉淀 → 复用"全链路 AI 原生整合**仍是蓝海
- AI（摘要、语义检索、自动分类）是让"被动堆砌"变"主动组织"的关键杠杆

### 1.4 目标用户

| 优先人群 | 特征 | 核心场景 |
|---|---|---|
| 知识工作者 | 阅读 5+ 篇/天，多设备 | 阅读沉淀、知识回溯 |
| 研究者/学生 | 大量资料检索 | 文献整理、引用追溯 |
| 重度浏览器用户 | 日均 50+ 标签 | Tab 治理、工具复用 |

### 1.5 核心价值主张

| 主张 | 含义 | 对竞品的差异 |
|---|---|---|
| **不用整理的收藏夹** | AI 全自动打标签、聚类、检索 | vs Cubox/Raindrop 的手动分类 |
| **有门槛的知识库** | 只有"已读+生成卡片"才进入 | vs Pocket 的"杂物间"模型 |
| **AI 原生全链路** | 从 Tab 到知识卡片一条龙 | vs 单点工具的割裂体验 |

## 2. 市场与竞品分析

### 2.1 竞品对比

| 维度 | Chrome 原生 | Cubox | Readwise Reader | Workona | **FlowShelf** |
|---|---|---|---|---|---|
| Tab 管理 | 基础 | ❌ | ❌ | ✅ | ✅ |
| 收藏管理 | 文件夹 | 文件夹+标签 | ❌ | ❌ | **纯多标签+语义检索** |
| 阅读沉淀 | ❌ | 弱 | ✅ | ❌ | ✅ |
| AI 摘要 | ❌ | 弱 | ✅ | ❌ | ✅ |
| 语义检索 | ❌ | ❌ | ❌ | ❌ | **✅（核心差异）** |
| 全链路整合 | ❌ | 部分 | 部分 | 部分 | **✅** |

### 2.2 差异化定位

```
                高 ┌──────────────────────────────┐
                   │                              │
   AI 原生程度     │      ★ FlowShelf（目标位）   │
                   │                              │
                   │  Readwise   Cubox            │
                   │                              │
                低 │  Pocket     Workona  Chrome  │
                   └──────────────────────────────┘
                   低      全链路整合程度      高
```

**核心差异化**：

1. 唯一做到"Tab → 待学 → 卡片"全链路 AI 自动化
2. 唯一做到"不用整理的收藏夹"（AI 多标签 + 语义检索）
3. 唯一做到"有门槛的知识库"（已读+生成卡片才入库）

## 3. 用户需求与场景

### 3.1 核心痛点（量化）

| 痛点 | 频率 | 痛苦程度 | 现有方案不足 |
|---|---|---|---|
| Tab 太多找不到 | 每日 | ★★★★★ | Chrome Tab Groups 太基础 |
| 收藏了找不到 | 每周 | ★★★★ | 文件夹模型结构性失败 |
| 读过就忘 | 每周 | ★★★★ | Pocket 只存不沉淀 |
| 工具网站记不住 | 每周 | ★★★ | 浏览器原生收藏越用越乱 |

### 3.2 关键用户场景

#### 场景 A：Tab 治理 + 知识沉淀

> 产品经理小王研究"RAG 优化"，开了 30+ 标签。
>
> 1. 点扩展 → AI 自动归为 5 组
> 2. "RAG 优化相关"8 个标签一键加入待学习
> 3. 逐篇阅读 → 点"生成卡片" → AI 10 秒生成摘要+关键观点+标签
> 4. 两周后开会，搜索"我读过 RAG"→ 5 张卡片秒回溯

#### 场景 B：工具收藏 + 快速复用

> 设计师小李收藏了 remove.bg，3 个月后想用。
>
> 1. 当初收藏时 AI 自动打标签 [设计][AI][图片处理]
> 2. 3 个月后搜索"我收藏过一个能去图片背景的网站"
> 3. AI 语义匹配 → remove.bg 秒出

#### 场景 C：待学习队列管理

> 学生小张收藏了 10 篇论文待读。
>
> 1. 7 天后 AI 提醒"2 篇即将过期"
> 2. 小张读完 5 篇生成卡片 → 进入知识库
> 3. 剩 5 篇"不学了" → 一键归档，不污染知识库

## 4. 产品架构

### 4.1 核心架构：三类内容池模型

```

│  │  终点站：    │    │  终点站：    │    │  终点站：    │    │

│  └──────────────┘    └──────────────┘    └──────────────┘    │
│         │                                        ▲           │
│         └──────────  价值门槛（读+生成卡片） ────┘            │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │           浏览器扩展（统一入口）                        │  │
│  │  Tab 管理 · 智能收藏分流 · 待学习队列 · 工具箱快捷入口  │  │
│  └────────────────────────────────────────────────────────┘  │

│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 三类内容池的边界规则

| 内容池 | 内容性质 | 流动方向 | 价值门槛 | 检索方式 |
|---|---|---|---|---|
| **待学习队列** | 知识型·待读 | 流向知识库 | 读+生成卡片才晋升 | 任务式回溯 + 过期提醒 |
| **工具箱** | 工具/娱乐·反复用 | **不流动（终点站）** | 无门槛 | 语义 + 多标签 + 频率 + 时间 |
| **知识卡片库** | 知识型·已沉淀 | **不流动（终点站）** | 已读+AI总结 | 语义 + 关联推荐 + 知识图谱 |

**核心设计原则**：

- **价值门槛**：只有"已读+生成卡片"的内容才进入知识库，保证知识库高信噪比
- **终点站原则**：工具箱和知识库都是终点，内容不互相流动，避免污染
- **零整理负担**：所有内容池的索引、标签、聚类均由 AI 自动完成

### 4.3 产品形态

| 形态 | 角色 | 用户何时用 |
|---|---|---|
| **浏览器扩展**（Chrome/Edge MV3） | 流量入口 + 即时操作 | 浏览网页时随手用 |
| **Web 应用**（flowshelf.app） | 知识大本营 + 深度整理 | 回顾、搜索、整理时用 |

移动端 MVP 阶段用响应式 Web 兜底，不做原生 App。

## 5. 功能详细设计

### 5.1 浏览器扩展

#### 5.1.1 Tab 管理工作台

**功能目标**：解决"开太多、找不到、不敢关"的 Tab 焦虑。

| 功能点 | 说明 |
|---|---|
| Tab 数量统计 | 实时显示当前 Tab 总数 |
| AI 自动归组 | 基于标题/URL/内容，AI 自动聚类为若干组 |
| 悬浮预览 | 鼠标悬停标签，预览网页缩略图 |
| 组级操作 | 整组转待学习 / 整组生成卡片 / 整组关闭 |
| 标签搜索 | 语义搜索标签标题或内容 |
| 智能清理建议 | AI 识别"重复""长时间未看""同一站点多个"等 |

#### 5.1.2 智能收藏分流

**功能目标**：用户点"收藏"时，AI 自动识别网页类型并建议归入哪个池。

```
收藏触发 → AI 识别网页类型 → 推荐归池 → 用户确认/修改
```

**识别规则**：

| 网页类型 | 默认归池 | 识别信号 |
|---|---|---|
| 在线工具/SaaS/API 文档 | 工具箱 | 域名特征、页面结构 |
| 博客/新闻/长文 | 待学习 | 正文长度、内容类型 |
| 视频（B站/YouTube） | 询问用户 | 域名 |
| 社交媒体 | 不收藏 | 域名黑名单 |

**用户可一键修改归池，AI 持续学习用户偏好。**

#### 5.1.3 待学习队列

**功能目标**：把"被动囤积"变"主动 To-Do"，倒逼用户读完。

| 功能点 | 说明 |
|---|---|
| 队列列表 | 按收藏时间倒序，显示标题+AI标签+收藏时间 |
| 过期提醒 | 7 天未读 → AI 提示"是否仍要学习？否则归档" |
| 即将过期区 | 置顶显示 6-7 天未读项 |
| 现在读 | 一键跳转原文 |
| 生成卡片 | 阅读后一键晋升到知识库 |
| 不学了 | 一键归档（不进知识库） |
| 批量操作 | 全部清空过期 / 批量生成卡片 |

**命名策略**：主名称"待学习"（传递目标感），副文案"稍后读"（降低压力）。

#### 5.1.4 工具箱快捷入口

扩展内提供工具箱快捷访问：

- 🔥 常用工具（3-5 个，按访问频率）
- 🔍 语义搜索框（"我收藏过一个能..."）

### 5.2 Web 应用

#### 5.2.1 知识卡片库（核心）

**功能目标**：用户已读+确认价值的知识沉淀大本营。

| 功能点 | 说明 |
|---|---|
| 卡片网格 | 默认 2 列，响应式自适应 |
| 时间筛选 | 今天/本周/本月/自定义 |
| 标签筛选 | 多标签 AND 交叉筛选 |
| 智能文件夹 | AI 自动聚类形成的虚拟视图（如"研究专题""产品灵感"） |
| 语义搜索 | "我读过关于 X 的文章" → AI 语义匹配 |
| 卡片详情抽屉 | 点击卡片右侧抽屉展开，不跳页 |
| 周报回顾 | 每周自动生成阅读总结 |
| 知识图谱（v2） | 卡片间关联可视化 |

#### 5.2.2 卡片详情

每张卡片包含以下区块：

| 区块 | 内容 | 交互 |
|---|---|---|
| 元信息 | 标题、阅读时间、阅读时长、原文链接 | 可点击原文 |
| 🤖 AI 摘要 | 100-200 字内容摘要 | 可重新生成 / 反馈好坏 |
| 💡 关键观点 | 3-5 条核心要点 | 可编辑 |
| 🏷️ AI 标签 | 自动抽取的多标签 | 可添加/删除 |
| ✍️ 我的批注 | 用户个人见解 | 可编辑 |
| 📎 关联卡片 | AI 推荐的相似卡片（带相似度） | 可点击切换 |

#### 5.2.3 工具箱（核心差异化）

**功能目标**：彻底解决"收藏了找不到"——做"不用整理的收藏夹"。

**5 层检索能力**：

| 层级 | 能力 | 解决场景 |
|---|---|---|
| 1. 语义搜索 | 自然语言描述 → AI 匹配 | "我收藏过一个能去图片背景的网站" |
| 2. 多标签交叉 | 多标签 AND 筛选 | 同时是"设计" AND "AI"的工具 |
| 3. 时间回溯 | 按收藏时间筛选 | "我记得上个月收藏的" |
| 4. 智能聚类 | AI 主动发现并建议归组 | "你最近收藏了 4 个 AI 绘图工具" |
| 5. 行为驱动排序 | 访问频率自动浮顶 / 沉睡归档 | 常用工具自动置顶，不用手动整理 |

**核心机制**：

- **零整理负担**：收藏时 AI 自动完成所有索引
- **多标签代替文件夹**：一条收藏可同时属于多个标签
- **行为信号**：访问次数、最近访问时间驱动排序
- **沉睡区**：90 天未访问自动归入，AI 建议清理

#### 5.2.4 周报回顾

每周自动生成：

- 读了 N 篇，生成 N 张卡片
- 热门标签 Top 5
- 关联发现："本周读的 3 篇都在讲 RAG"
- 待学习队列健康度：X 条待读，Y 条即将过期

## 7. AI 能力设计

### 7.1 AI 引擎总览

```
┌─────────────────────────────────────────────────────┐
│                  AI 引擎（贯穿全产品）                │
├─────────────────────────────────────────────────────┤
│  输入处理层                                          │
│  ├─ Tab 自动归组（基于标题+URL+内容聚类）            │
│  ├─ 网页类型识别（工具/文章/视频/娱乐）              │
│  └─ 内容正文抽取（去广告/导航/页脚）                 │
│                                                     │
│  索引构建层                                          │
│  ├─ 多标签自动抽取（一条内容 N 个标签）              │
│  ├─ 内容摘要生成（100-200 字）                       │
│  ├─ 关键观点抽取（3-5 条）                           │
│  └─ 向量索引（用于语义检索）                         │
│                                                     │
│  检索与推荐层                                        │
│  ├─ 语义搜索（自然语言 → 匹配内容）                  │
│  ├─ 关联推荐（卡片相似度计算）                       │
│  ├─ 智能聚类（发现用户收藏的潜在分组）               │
│  └─ 行为驱动排序（访问频率 + 时间衰减）              │
└─────────────────────────────────────────────────────┘
```

### 7.2 核心 AI 能力清单

| 能力 | 输入 | 输出 | 触发时机 |
|---|---|---|---|
| Tab 归组 | 当前所有 Tab 元信息 | 分组结果 | 用户打开扩展 |
| 网页类型识别 | URL + 页面 DOM | 类型标签 | 收藏时 |
| 多标签抽取 | 网页标题+描述+正文 | 3-5 个标签 | 收藏时 |
| 内容摘要 | 正文 | 100-200 字摘要 | 生成卡片时 |
| 关键观点 | 正文 | 3-5 条要点 | 生成卡片时 |
| 语义检索 | 用户自然语言查询 | 相关度排序结果 | 用户搜索时 |
| 关联推荐 | 当前卡片向量 | Top 3 相似卡片 | 查看卡片时 |
| 智能聚类 | 用户所有收藏 | 聚类建议 | 每周/触发式 |
| 行为排序 | 访问日志 | 排序后的列表 | 实时计算 |

### 7.3 LLM Provider 策略

- 主模型：OpenAI GPT-4o-mini（摘要、标签、分类）
- 嵌入模型：text-embedding-3-small（语义检索）
- 备选：通义千问（DEMO_MODE 切换）
- 所有 AI 输出必须经过 Pydantic 校验（结构化输出）

## 8. 数据模型（高层）

### 8.1 核心实体

```
User
 ├─ TabSession（临时，关闭即清）
 ├─ Bookmark
 │   ├─ type: learning | tool
 │   ├─ status: pending | read | archived
 │   ├─ tags[]（多标签）
 │   ├─ visit_count
 │   ├─ last_visited_at
 │   └─ ai_index（向量+摘要+类型）
 └─ Card（知识卡片）
     ├─ source_url
     ├─ ai_summary
     ├─ key_points[]
     ├─ tags[]
     ├─ annotation
     ├─ related_cards[]
     └─ read_at
```

### 8.2 关键关系

- 一个 Bookmark（learning 类型）→ 生成一个 Card
- 一个 Bookmark（tool 类型）→ 独立存在，不生成 Card
- 一个 Card → 关联多个 Card（双向，带相似度）
- 一个 Bookmark/Card → 多个 Tag（多对多）

## 14. 关键决策记录

以下决策在需求讨论中确定，是产品设计的基石：

| # | 决策 | 理由 | 影响 |
|---|---|---|---|
| 1 | **聚焦构思 5/1/2 整合 MVP** | RICE 评分最高，全链路协同 | 砍掉构思 3/4/6 进入 MVP |
| 2 | **浏览器扩展 + Web 应用双形态** | 扩展做入口，Web 做沉淀 | 移动端延后 |
| 3 | **拆分"待学习队列"与"知识卡片库"** | 未读内容不污染知识库 | 收藏夹从 Web 大本营剥离 |
| 4 | **"待学习"命名（副标题"稍后读"）** | 目标感强 + 降低压力 | 替代"收藏夹"概念 |
| 5 | **新增"工具箱"作为第三类内容池** | 工具类网页不需沉淀为知识 | 覆盖完整数字资产类型 |
| 6 | **工具箱抛弃文件夹，用多标签+语义检索** | 文件夹模型结构性失败 | 核心差异化 |
| 7 | **价值门槛：读+生成卡片才进知识库** | 保证知识库高信噪比 | 与 Cubox/Pocket 本质差异 |
| 8 | **AI 全自动索引，零整理负担** | AI 时代的根本性突破 | 用户全程只做"确认/修正" |
