# Tab 管理页核心逻辑

> 本文档定义了 FlowShelf Tab 管理台（`/tabs`）的完整交互逻辑，是开发实现的唯一参照。

## 一、页面加载

| 步骤 | 说明 |
|---|---|
| 1. 检测扩展 | `checkBridgeAvailable()`，不可用显示安装引导 |
| 2. 拉取标签 | `getAllTabs()` 获取所有窗口的 HTTP/HTTPS 标签 |
| 3. 判断分组 | 检查是否有标签属于 Chrome 原生群组（`groupId !== -1`） |
| 4a. 有 Chrome 群组 | 按群组名分组，保留群组颜色；未分组的标签放入「未分组」卡片（排在最后） |
| 4b. 无 Chrome 群组 | 按窗口分组（窗口 1、窗口 2…） |
| 5. 不调 AI | 页面加载不触发 AI 分组，仅反映浏览器实际状态 |

## 二、非编辑模式

### 按钮
仅 `✏️ 编辑`

### 实时事件（全部生效）

| 事件 | 处理 |
|---|---|
| 新标签创建（无 Chrome 群组） | → 追加到「未分组」（不存在则末尾创建） |
| 新标签创建（有 Chrome 群组） | → 查 Chrome 群组名，加入对应分组 |
| 标签关闭 | → 从状态移除，所在分组自动缩减 |
| URL/标题变更 | → 原地更新，不改变分组 |
| 标签在浏览器中换群组 | → 从原分组移除，加入新 Chrome 群组对应分组（或「未分组」） |
| Chrome 群组改名 | → 更新对应分组的名称 |
| Chrome 群组解散 | → 该分组所有标签移入「未分组」 |

### 用户操作

| 操作 | 效果 |
|---|---|
| 点击标签 | 激活浏览器对应标签 |
| hover 标签 | 显示「卡片」「工具」「✕」按钮 |
| 点击「卡片」 | 收藏为知识卡片到待学习队列 |
| 点击「工具」 | 收藏为工具到待学习队列 |
| 点击「✕」 | 关闭该标签 |
| 点击「✕ 整组关闭」 | 弹出 popover 二次确认 → 关闭该组所有标签 |
| 点击「✏️ 编辑」 | 进入编辑模式 |

## 三、编辑模式

### 按钮
`🤖 AI智能分组` ｜ `✕ 取消编辑` ｜ `✨ 一键同步`

### 实时事件（部分生效）

| 事件 | 处理 | 理由 |
|---|---|---|
| 新标签创建 | ✅ → 加入「未分组」 | 新标签必须可见，否则同步时遗漏 |
| 标签关闭 | ✅ → 从状态移除 | 已关闭的标签不能被同步 |
| URL/标题变更 | ✅ → 原地更新 | 不影响分组结构 |
| 标签换群组（浏览器侧） | ❌ 忽略 | 保护用户的手动分组编辑 |
| 群组改名（浏览器侧） | ❌ 忽略 | 用户可能正在改名 |
| 群组解散（浏览器侧） | ❌ 忽略 | 会破坏用户的分组编辑 |

### 用户操作

| 操作 | 效果 |
|---|---|
| 拖拽标签 | 同组内排序 / 跨组移动（仅改本地状态，不同步浏览器） |
| 点击组名 | 进入组名编辑（Enter 确认，Esc 取消） |
| 点击「➕ 新建分组」 | 末尾创建空分组卡片 |
| 点击「🗑 删除组」 | 删除空分组（非空组拒绝删除） |
| 点击「🤖 AI智能分组」 | 调后端 AI 对当前标签重新归组，留在编辑模式 |
| 点击「✕ 取消编辑」 | 调 `loadTabs()` 重新加载浏览器最新状态，退出编辑模式。用户本次所有编辑丢弃 |
| 点击「✨ 一键同步」 | 当前分组（过滤空组后）→ 同步为 Chrome 原生群组，退出编辑模式。用户编辑覆盖浏览器状态 |

### 编辑模式下不可用的操作
- 标签的「卡片」「工具」「✕」按钮隐藏（只显示拖拽柄 + 标题）
- 「✕ 整组关闭」隐藏（只显示空组的「🗑 删除组」）

## 四、核心原则

1. **非编辑模式 = 浏览器状态的镜像**。所有浏览器侧操作实时同步，tabs 页面不主动改变分组。
2. **编辑模式 = 调整中间态**。用户可以偏离浏览器状态做调整，Tab 存在性仍同步，分组结构冻结。
3. **取消编辑 = 回归真实**。reload 浏览器最新状态，用户编辑全部丢弃。
4. **一键同步 = 写回浏览器**。用户编辑覆盖浏览器群组，已关闭的 tab 不会复活，新建的 tab 被纳入用户指定的分组。
5. **AI 分组仅在用户主动点击时触发**，页面加载和实时事件都不调 AI。

## 五、技术实现要点

### 5.1 Background 脚本事件转发

| Chrome API 事件 | 转发为 | 说明 |
|---|---|---|
| `tabs.onCreated` | `tabEvent: created` | 包含 `groupId` |
| `tabs.onUpdated` | `tabEvent: updated` | 如果 `changeInfo` 含 `groupId`，额外转发为 `grouped` 事件 |
| `tabs.onRemoved` | `tabEvent: removed` | |
| `tabGroups.onCreated` | `groupEvent: created` | 群组创建 |
| `tabGroups.onUpdated` | `groupEvent: updated` | 群组改名/改色 |
| `tabGroups.onRemoved` | `groupEvent: removed` | 群组解散 |

### 5.2 Chrome Bridge 扩展

```ts
type TabEventType = 'created' | 'updated' | 'removed' | 'grouped';

interface GroupEventData {
  event: 'created' | 'updated' | 'removed';
  group: { id: number; title: string; color: string; windowId: number };
}
```

### 5.3 群组信息缓存

页面加载时调用 `getTabGroups()` 获取所有 Chrome 群组信息（id → name/color），缓存在 ref 中。后续事件通过 `groupId` 查缓存即可。

### 5.4 编辑模式事件过滤

```ts
// 编辑模式下：仅处理 tab 存在性事件，忽略群组级事件
if (editMode && (event === 'grouped' || data is groupEvent)) return;
```
