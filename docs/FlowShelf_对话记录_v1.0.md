## 对话背景

用户提出 6 个一句话需求构思，希望以资深 AI 产品经理视角进行必要性、优先级、商业化价值、实现难度的全面分析，并输出 PRD 与开发计划。

### 原始 6 个构思

1. 浏览器 tab 管理：开太多，缩小后难以查看和关闭
2. 浏览器收藏夹管理：收藏太多，文件夹混乱，找不到收藏内容
3. 提示词管理助手：好用的提示词需要保存供复用
4. 桌面文件整理：多版本文件不好区分，桌面混乱
5. 文章内容总结卡片：好文章总结归纳，快速回溯阅读历史
6. 各银行/股票账户余额管理：多账户支付，难以统计花费与资产

### 第 4 轮：收藏夹定位修正（关键决策）

**用户质疑**：收藏夹放在 Web 应用里存在歧义。Web 大本营应该是"已读+确认价值"的内容汇总，收藏夹存放的是待读内容，未读内容出现在大本营有歧义。建议改名为"待学习内容"。

**AI 判断**：**完全赞同**，认为这关系到整个产品的定位清晰度。

#### 痛点本质
"收藏夹"是语义模糊的概念，同时混了三种状态：
- 看到有意思，等下读（待办）
- 读完了，值得留存（沉淀）
- 不知道用不用得上，先存着（囤积）

结果：收藏夹变成"杂物间"，污染"个人知识库"的可信度。

#### 核心修正：拆成"输入层"与"沉淀层"
```
输入层（浏览器扩展侧）        沉淀层（Web 大本营）
├─ Tab 临时区                 └─ 知识卡片库（只放已生成卡片）
└─ 待学习队列（替代收藏夹）        + 关联图谱 / 周报回顾
```

**关键变化**：
- 待学习队列留在浏览器扩展侧，不进入 Web 大本营
- 只有用户真正读过 + 生成卡片，内容才会"晋升"到 Web 知识库
- Web 大本营从此有"门槛"，内容含金量保证

#### 命名决策
- 主名称用"待学习"（传递目标感，提升阅读转化率）
- 副文案用"稍后读"（降低压力）
- 配套过期提醒（7 天未读 → AI 提示"是否仍要学习"）

#### 三个核心收益
1. 大本营可信度大幅提升（搜索结果 100% 是已读内容）
2. 阅读转化率提升（待学习 + 过期提醒倒逼读完）
3. 产品定位更清晰（扩展=输入与待办；Web=沉淀与回顾）

### 第 5 轮：工具箱重构（关键决策）

**用户痛点**：用户不仅阅读知识型网页，还会收藏工具类/娱乐类网页。这些不需要沉淀为知识，但要快速找到重复使用。传统收藏夹由于文件夹创建过多、分类不清晰、误触，导致"我记得收藏过但找不到"。

**AI 判断**：**应该做，但绝不能做成"又一个收藏夹"**。

#### 痛点本质：传统收藏夹的"结构性失败"

1. **归属冲突**：内容天然是多维的，文件夹只能装一维
   - 一个网站（remove.bg）同时是设计工具、AI 工具、图片处理工具、常用工具
   - 文件夹逼用户选一个，结果找不到

2. **记忆失真**：人记的是"语义"，文件夹存的是"路径"
   - 用户回想："我好像收藏过一个能去掉图片背景的网站"
   - 传统收藏夹只能按路径找，必然找不到

3. **维护成本**：分类是反人性的"前置负担"
   - 人脑是用的时候才知道需要什么维度

#### 核心解法：抛弃文件夹，用"AI 多维索引"重构

```
一条收藏 = 网址 + 元数据
├─ AI 自动抽取（收藏瞬间完成）
│  ├─ 标题、描述、favicon、截图
│  ├─ 多标签：[设计] [AI] [图片处理] [常用]
│  ├─ 内容摘要（用于语义搜索）
│  └─ 类型识别：工具/文章/视频/娱乐
└─ 行为信号（持续积累）
   ├─ 访问次数、最近访问时间
   ├─ 收藏时间
   └─ 用户手动修正的标签
```

#### 产品架构调整：新增"工具箱"作为第三类内容池

| 内容池 | 内容性质 | 流动方向 | 价值门槛 |
|---|---|---|---|
| 待学习队列 | 知识型·待读 | 流向知识库 | 读+生成卡片才晋升 |
| **🆕 工具箱** | 工具/娱乐·反复用 | **不流动（终点站）** | 无门槛 |
| 知识卡片库 | 知识型·已沉淀 | **不流动（终点站）** | 已读+AI总结 |

**核心边界**：工具箱是终点站，不是中转站。工具类网站进去后就留在那里反复使用，不需要"晋升"到知识库。

#### 收藏时的智能分流
用户点"收藏"时，AI 根据网页类型自动建议归入哪个池：
- 工具类（在线工具、SaaS、API 文档）→ 默认进工具箱
- 文章类（博客、新闻、长文）→ 默认进待学习
- 视频类（B站/YouTube）→ 询问用户

#### 工具箱 5 层检索能力

| 层级 | 能力 | 解决场景 |
|---|---|---|
| 1. 语义搜索 | 自然语言描述 → AI 匹配 | "我收藏过一个能去图片背景的网站" |
| 2. 多标签交叉 | 多标签 AND 筛选 | 同时是"设计" AND "AI"的工具 |
| 3. 时间回溯 | 按收藏时间筛选 | "我记得上个月收藏的" |
| 4. 智能聚类 | AI 主动发现并建议归组 | "你最近收藏了 4 个 AI 绘图工具" |
| 5. 行为驱动排序 | 访问频率自动浮顶 / 沉睡归档 | 常用工具自动置顶 |

#### 与竞品的本质差异

| 维度 | 传统收藏夹 | Cubox/Raindrop | **FlowShelf 工具箱** |
|---|---|---|---|
| 组织模型 | 文件夹（一对一） | 文件夹+标签（混合） | **纯多标签（扁平）** |
| 收藏负担 | 高 | 中 | **零（AI 全自动）** |
| 检索方式 | 路径导航 | 关键词+标签 | **自然语言语义检索** |
| 长期维护 | 越用越乱 | 越用越乱 | **自动沉睡+清理建议** |

**核心差异**：不是"更好的收藏夹"，而是"不用整理的收藏夹"——AI 时代才能做到的根本性突破。

## 关键决策汇总

以下决策在讨论中确定，是产品设计的基石：

| # | 决策 | 理由 | 影响 |
|---|---|---|---|
| 1 | 聚焦构思 5/1/2 整合 MVP | RICE 评分最高，全链路协同 | 砍掉构思 3/4/6 进入 MVP |
| 2 | 浏览器扩展 + Web 应用双形态 | 扩展做入口，Web 做沉淀 | 移动端延后 |
| 3 | 拆分"待学习队列"与"知识卡片库" | 未读内容不污染知识库 | 收藏夹从 Web 大本营剥离 |
| 4 | "待学习"命名（副标题"稍后读"） | 目标感强 + 降低压力 | 替代"收藏夹"概念 |
| 5 | 新增"工具箱"作为第三类内容池 | 工具类网页不需沉淀为知识 | 覆盖完整数字资产类型 |
| 6 | 工具箱抛弃文件夹，用多标签+语义检索 | 文件夹模型结构性失败 | 核心差异化 |
| 7 | 价值门槛：读+生成卡片才进知识库 | 保证知识库高信噪比 | 与 Cubox/Pocket 本质差异 |
| 8 | AI 全自动索引，零整理负担 | AI 时代的根本性突破 | 用户全程只做"确认/修正" |
